# Vanta v1.4.0 — IPv6 rebuild with sticky sessions

**Release date:** 2026-09-30

### Install

```bash
go install github.com/muxover/vanta@v1.4.0
```

---

## Summary

A rebuild of Vanta as an IPv6-only rotating proxy. It fixes the bugs that made earlier versions unreliable, adds sticky sessions and a client allowlist, and retracts v1.0.0 through v1.3.0.

---

## What's included

### IPv6 only

- `bind_prefixes` takes IPv6 prefixes; IPv4 pools, `fallback_prefixes` and `replace_ips` are gone.
- Sites with no IPv6 address are refused by default, so nothing leaves from the server's own address. `ipv4_targets: direct` reaches them without rotation.
- A local route on `lo` is added for each prefix and removed on exit (`add_routes`); a prefix that contains the server's gateway is refused, so a shared on-link range can't cut the server off.

### Sessions and access

- Sticky sessions: `user-session-<id>` keeps one address, derived from the id with nothing stored.
- `allow_ips` limits which clients can connect.
- Private, link-local, CGNAT, multicast and metadata destinations are blocked by default.
- Addresses inside the bind prefixes and the proxy's own port are always refused, so the proxy can't be turned on its own server.

### Protocol handling

- WebSocket upgrades, `Expect: 100-continue`, chunked bodies and pipelined requests over plain HTTP.
- Client keep-alive holds even when the upstream closes after each response; every request still gets a new address.
- Bytes sent right behind CONNECT or a SOCKS5 request reach the target.
- SOCKS5 answers with the bound address and the correct reply codes.

### Operations

- Every config error is reported at startup; `-check` validates without starting.
- SIGHUP reloads everything except the listen and metrics addresses.
- Prometheus metrics for requests, rejections, DNS and dial failures and blocked destinations.
- System-wide TCP tuning is opt-in with `tune_kernel`.

---

## Fixed

- SOCKS5 refused every client when the config had no `auth` section.
- Plain HTTP downloads were cut at `idle_timeout` while data was still flowing.
- Early bytes after CONNECT were dropped.
- Route registration always failed.
- Dual-stack hostnames always resolved to IPv6 regardless of the pool.
- An empty `bind_prefixes` sent traffic from the server's own address.
